# Tests that deliberately assert nothing, one per line, as:
#
#     test_file.py::test_name  # why this cannot assert an outcome
#
# Before adding an entry, try harder to assert the observable outcome. "It must
# not raise" is a real contract, but it is almost always expressible as
# something checkable — no task created, nothing cancelled, state unchanged. An
# entry here says that check was attempted and is not available, not that it
# was inconvenient.
#
# A stale entry (naming a test that no longer exists, or one that now asserts)
# is reported as a failure, so this file cannot quietly rot.
#
# ---------------------------------------------------------------------------
# Reviewed 2026-08-07. The audit reported 10; eight were rewritten to assert an
# outcome and are gone from this list. The two below are the acceptance half of
# a boundary pair, and acceptance genuinely has no observable form:
# `_validate_sms_length` returns `None` and raises on rejection, so the only
# available assertion is `is None`, which is the trivial bolt-on dev_standards
# §11 forbids. Each is paired with a neighbouring test asserting the raise one
# character further on, and `test_a_message_between_the_two_limits_turns_on_
# content_alone` asserts the distinction the pair exists to draw. Deleting the
# limit check fails that third test, so these two are not the only guard.
# ---------------------------------------------------------------------------
